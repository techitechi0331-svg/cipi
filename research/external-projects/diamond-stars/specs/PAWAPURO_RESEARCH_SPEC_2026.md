## 2. コアゲームループ (操作の構造)

**[D] 基本状態:** `MENU -> MATCH_SETUP -> PRE_PITCH -> PITCH_TYPE -> AIM -> WINDUP -> BALL_IN_FLIGHT -> {TAKE|SWING|HIT_BY_PITCH} -> {COUNT_RESOLUTION|BALL_IN_PLAY} -> FIELDING -> THROW/RUNNING -> OUT/SAFE/SCORE -> NEXT_BATTER -> SIDE_CHANGE -> GAME_END`

- 攻撃側は打順・打者能力・打撃方式 (ミート/強振/バント) を決め、カーソルを動かして投球を待つ。
- 守備側は投手・球種・コース・守備シフト・牽制を決め、投球タイミング入力を行う。
- 投球中は物理位置から見えるボールと、ヒッティングポイントへの到達時刻を単一の時間系で解決する。
- 打球発生後はカメラ・操作担当野手が切り替わり、落下位置・反応・移動・捕球可否・送球の精度/速度が結果を変える。
- ボールデッド後に走者・アウト・得点・打席結果を確定し、次の打席/攻守交代へ進む。

**品質基準:** 結果を先にサイコロで確定して演出するだけの仕様は禁止。少なくとも球種軌道、打球物理、野手到達、走者・送球到達時間は**実シミュレーション**から決まること。[D]

## 3. 打撃システム

### 3.1 打撃方式

- **ミート打ち:** 打ちやすさを優先し、比較的大きなミートカーソルで打球を合わせる。[O アプリ][C]
- **強振:** ミートカーソルが小さくなって難しくなる代わりに打球を遠くへ飛ばしやすくなる。[C]
- **バント:** バットを当てて球を転がす戦術。**セーフティ、送り、スクイズ**は野球のルールとして後続機能へ。[D]
- **ロックオン:** 打撃補助レベル0–3が大会資料に記載。[P] 家庭用最新版で全場面同一段階とは断定しない。
- **入力方式:** アプリ公式ヘルプでは「スライドでミートカーソル移動→指を離してスイング」が案内されている。[O アプリ] 家庭用のボタン割当はハード・操作タイプで別途設定。

### 3.2 当たり判定・タイミング [D]

- ストライクゾーンの `targetX`,`targetY` とミートカーソルのスクリーン/打撃平面座標を完全一致させ、左右反転バグを排除。
- 時刻差 `timingError = |swingContactTime - ball.crossPlateTime|`、芯の距離 `aimError = length(cursorPosition - ballPositionAtPlate)` の2軸で判定。
- `batQuality = f(contactAbility, batMode, timingError, aimError, pitchMovement, ballSpeed, playerTraits, condition)`。
- 弾道（打球角度）は `launchAngle = baseSwingPlane + trajectoryFactor + timingBias + contactPointOffset + traitBonus` で独立管理。
- 打球初速は `batSpeed × ballImpact × powerFactor × sweetSpotFactor` から求め、最後に校正テーブルでゲームらしい爽快感に寄せる。
- 明確な判定は `PERFECT / GOOD / WEAK / FOUL / MISS / TAKE`。好打者でも毎回打てないようランダムブレは小さく再現可能な乱数で注入。
- フェア/ファウル・飛球/ライナー/ゴロは飛行方向、初速、回転、角度から判定する。

### 3.3 打撃UI/カメラ [D]

1. 打席カメラは打者の斜め後方から投手を正面に捉え、ホーム側の打撃面が視認できる立体球場。
2. **ストライクゾーンの真上**に小型タイミングゲージ（画面幅に対して適応表示、ゾーンや打球を隠さない）。
3. ボール接近に連動する**縮小リング**は到達位置へ収束するが、実際のボール軌道が優先。リングの減速・点滅・効果音はアクセシビリティで調整可。
4. スコア/回・表裏/走者/BSOを上側に、投手/打者の要点情報を左側下方に表示。守備画面では一時的に機能中心のHUDへ切り替える。
5. 遅延やフレーム落ちがあってもリング、音、判定は**同一のシミュレーション時刻**を参照。コマ送りで判定がずれない。

## 4. 投球システム

### 4.1 コースと操作

- **[D] 提案する操作順序:** 「球種を選択 → 狙うコースを決定 → 投球入力」。途中で球種/コースを戻せ、最終選択を投手の手元からホーム側へ投げる。
- **ナイスピッチ:** パワプロアプリ公開ルールでは投球ゲージの白色部分で止めると球威が高く、黄→緑→赤と変化するという説明がある。[O アプリ] **この色順・効果は家庭用2026の統一仕様とは断定しない**。
- **牽制:** アプリ公開対戦ルールでは盗塁中走者の牽制、投球時スタミナ消費、前進守備との関係が示されている。[O アプリ]
- **投手の能力:** 球速、コントロール、スタミナ、変化球の種類と変化量。アプリ公式ヘルプでは変化球は**5方向・7段階**の概念。[O アプリ]

### 4.2 球種・軌道分類

| 系統 | 代表球種 | プレイヤー視点の特徴 | 根拠 |
|---|---|---|---|
| 速球 | ストレート、全力ストレート | 速く直線的、球威差 | [C] |
| 動く速球 | ツーシーム、ムービングファスト、カットボール | 速度を保ちつつ小さく揺れる/切れる | [C] |
| 横変化 | スライダー、Hスライダー、シュート、Hシュート | 右/左へ曲がり、利き腕で符号が反転 | [C] |
| 斜め変化 | カーブ、スローカーブ、ドロップ、スラーブ、ナックルカーブ、パワーカーブ | 横成分と落差、遅さの組合せ | [C] |
| 縦変化 | フォーク、SFF、Vスライダー、パーム | リリース後の落下・キレが異なる | [C] |
| 緩急 | チェンジアップ、サークルチェンジ、超スローボール | 球速・減速度で打者のタイミングを外す | [C] |
| その他 | シンカー、Hシンカー、ナックル、オリジナル変化球 | 左右斜め・不規則・独自パラメータ | [C] |

**[C] コミュニティの2026–2027球種解析**では、方向角、変化量、球速、ブレーキ、キレ、消費スタミナなどの概念と数値テーブルが掲載されている。ユーザー測定を含むため**公式の内部式ではない**。特に「キレ＝変化開始が遅く、短時間で鋭く変化」「ブレーキ＝到達までの減速」の説明は独自実装の設計に有益。

### 4.3 球道シミュレーション [D]

- 3D位置を `P(t) = P0 + forward * forwardProgress(t) + horizontalBreak(t) + verticalBreak(t) + gravityDrop(t)` とし、`t∈[0,1]`。
- 変化量 `level` は**各球種別1–7**。方向 `direction`、変化開始 `breakStart`、急峻さ `sharpness`、減速 `drag`、球速 `velocity`、重さ `ballWeight` を独立パラメータ化。
- `smoothStep((t - breakStart)/(1 - breakStart))` を曲がりの基底とし、終盤にカーブ/スライダー/フォークごとの関数を適用。投球開始点から到達点へ**破綻なく連続**する軌道であること。
- ボールの3D位置をそのまま投球・打撃双方の画面へ投影する。投球後に画面上でボールが突然曲がるような2D座標ジャンプはしない。
- 投手別の球種保有・変化量・方向・投球フォーム・左右・疲労・制球・球速を反映。
- 軌道の残像は**表示補助**であり、実球の位置・当たり判定を必ず一致させる。
- CPU打者の球種読みに対し、初期軌道/変化開始/球速差から予測を更新させる。AIが着弾点を最初から完全把握する設計は禁止。

### 4.4 オリジナル球種 [D]

- `name`, `family`, `speedMultiplier`, `breakX`, `breakY`, `lateBreak`, `sharpness`, `brake`, `spin`, `staminaCost`, `rarity` を持つ。
- 総変化量・属性上限・対戦バランスを独立ルールで制限。公式の名称・エフェクトを流用しない。

## 6. 守備シミュレーション

### 6.1 実際に存在する要素

- 野手の**走力・肩力・守備力・捕球**は別々の能力として扱われる。[O アプリ]
- 「練習」で守備やダイビングキャッチを学習できる。[O 2026本編]
- 対戦環境には守備操作の手動/自動、守備シフト、フォーメーション、送球操作タイプ、落下地点表示、守備ズームなどの項目がある（公開大会資料は**別タイトル『WBSC eBASEBALL パワフルプロ野球』**であるため、本編2026への同一性は未確認）。[P]
- 青特殊能力・守備系の上位能力は守備プレーに補正を与えると攻略資料で説明される。[C]

### 6.2 本格3D守備の最低条件 [D]

1. **3Dフィールド:** 内外野を同一のワールド座標系で保持。守備画面は2D俯瞰画像への切替ではなくカメラだけ切替。
2. **選手の速度:** 初速・加速度・最高速・減速を別々に管理。毎フレーム位置を一定速度でワープさせない。
3. **選手の反応時間:** `reactionTime = baseReaction - fieldingBonus + readError`。好守備選手は早く動き始める。
4. **打球到達予測:** 実際の空気抵抗・重力・バウンド・地面摩擦を計算。野手AIは未来の落下地点を予測するが、予測精度は守備能力次第で誤差がある。
5. **捕球状態:** `IDLE -> ANTICIPATE -> RUN -> SET_FEET -> CATCH_ATTEMPT -> HOLD -> THROW_WINDUP -> RELEASE -> FOLLOW_THROUGH`。
6. **捕球可否:** ボール中心との距離、グラブの到達範囲、姿勢、相対速度、プレイヤーの入力、捕球能力で判定。
7. **捕球ミス:** `CATCH / BOBBLE / DROP / MISS`。確率は捕球・球速・難しい姿勢・天候などで変化。
8. **送球:** 目標塁までの3D軌道と時間を持つ。肩力は送球球速・伸び、守備力は持ち替え/送球準備、捕球は受球安定性に影響。
9. **カバー:** 1塁ベースカバー、二塁フォース、中継、カットプレー、捕手ブロックをAIで制御。9人制の守備ポジションをきちんと配置（投手・捕手・1/2/3塁・遊撃・左/中/右翼）。
10. **操作:** WASDで移動 / Tabで対象選手切替 / ダイビング / ジャンプ / 捕球 / 指定塁への送球 / 中継送球 / シフト変更。キーは後からゲームパッド対応可能に。

### 6.3 速度・反応の標準式 [D、仮値]

- `speedMps = 4.1 + 0.045 * runAbility`（例: 走力40→5.9 m/s、走力90→8.15 m/s）。**本家での計算式ではない**。
- `accelMps2 = 3.2 + 0.023 * runAbility`。入力直後に即最高速へはならない。
- `reactionS = clamp(0.63 - 0.003 * fielding, 0.20, 0.65)`。待機しているAI選手にだけ適用し、手動選手には入力遅延を追加しない。
- `pickupS = clamp(0.8 - 0.0055 * fielding, 0.22, 0.78)`。守備力は「移動速度」ではなく球の扱いの上手さにも効く。
- `throwV = 19 + 0.19 * armStrength` m/s。距離と助走で補正し、中継を活用。
- `catchRadius`は能力による加算より、姿勢・グラブリーチ・アニメーション位置を優先。
- 走力80の野手と走力40の野手を同じ距離へ走らせた比較で、到達時間に差が見えること（受入試験）。

### 6.4 カメラ設計 [D]

- 打球発生直後: 打席から打球を追う**打球追従3Dカメラ**。
- 高いフライ: カメラは落下地点と捕球候補を同時に収める。カメラ追従の急旋回制限。
- ゴロ: 内野を見せ、送球先ベースもフレームに入れる。
- 外野打球: 外野手へのスムーズな追従と中継先の方向表示。
- リプレイ: 打球初速/角度/飛距離を別のカメラで再生。実プレーの録画でなく状態ログから再描画できる設計。
- 表示サイズが狭い時も、操作選手・ボール・落下地点・送球先が必ず見える構図へ自動調整。

## 7. 走塁システム

### 7.1 仕様範囲 [D]

- 走者が0–3塁に複数存在しても各走者を**独立エンティティ**として管理。`runnerId`, `fromBase`, `toBase`, `distance`, `speed`, `lead`, `runningState`, `forced`, `taggedUp`を持つ。
- ゴロ時の打者走者、フォースプレー、タッチアウト、フライ捕球後の帰塁、タッチアップ、盗塁、牽制、挟殺、暴投、捕逸、ホーム突入、犠牲フライを扱う。
- 走力は最大速度に関わる一方、盗塁のスタート/投手モーション観察/帰塁は別のスキルで変化させる。
- 送球到達時刻と走者のベース到達時刻を比較し、塁・走者ごとのルールを適用。**「打球が強いから2塁打」など事前確定しない**。
- ベースを踏んだ時刻、帰塁の有無、送球先選択、捕球完了をタイムスタンプで記録。

### 7.2 AI [D]

- 止まる/進む/戻る/走る/盗塁を状態として選択。
- 走者個々の `aggressiveness`, `baseRunning`, `stealSkill` とアウト数、打球の種類、守備選手の肩力、位置から意思決定。
- ダブルプレーとタッチアップの最低限の判断を追加。走者が同じ塁を占有したまま試合が進む等の破綻を回避。

## 8. 試合ルール・スコアリング [D、現行の基本的な野球規則に基づく]

**通常の野球規則として扱う主要事象:** 3アウトで攻守交代、3ストライク（条件に応じ三振）、4ボール（四球）、フェア/ファウル、ヒット/エラー/野選、併殺、犠打/犠飛、触塁・フォース/タッチ、走者の帰塁、得点、サヨナラ、延長、引き分け規則。

- **ルール設定:** 1/3/5/9イニング、延長有無・上限、DH有無、タイブレーク、コールド、エラー、怪我/疲労をデータで設定。[D]
- **本編参考:** 『2026–2027』ペナントでは12球団以外も使用可能、独自のチーム特殊能力や育成要素を実装。[O] `RuleSet`は対戦/育成/大会で切り替える。
- **集計:** 打者：打席/打数/安打/二塁打/三塁打/本塁打/打点/四球/三振/盗塁、投手：投球数/被安打/自責点/失点/奪三振/四死球/球速/各球種比率、守備：刺殺/補殺/失策など。
- **絶対条件:** 表裏の反転/打順の進行/次回の先頭打者/勝敗/記録が同時に破綻しない。得点判定と球種・球速表示は単一の公式状態から描画する。
- **注意:** プロ野球公式戦・高校野球・国際大会などはDH、延長、コールド、タイブレーク等の細則が異なるため**「本家がすべて同じ規則」ではない**。DIAMOND STARSはルールプリセットで差を吸収する。

## 9. CPU/AIと難易度

| 階層 | AI の意思決定 | 能力値との関係 | 実装条件 [D] |
|---|---|---|---|
| 投手AI | 球種/コース配球、速球と変化球の緩急、疲労、走者ケア | 球種、制球、スタミナ、特殊能力 | 全球ストライク/完全ランダム配球を避ける |
| 打者AI | 球種認識、変化予測、待球、スイング、ミート/強振選択 | ミート、パワー、選球眼、調子 | ボールを100%先読みしない |
| 守備AI | 打球予測、捕球選択、カバー/中継、送球塁判断 | 走力、守備、捕球、肩力 | 通常プレーで人間の野手を追い越さない速度 |
| 走塁AI | 進塁/帰塁/盗塁/タッチアップ、ギャンブル走塁 | 走力、走塁、盗塁、性格 | 打球と送球時間に基づく判断 |
| 監督AI | 代打、交代、守備シフト、送りバント、敬遠 | 選手能力、試合状況、長期戦略 | P3以降で導入 |

**難易度:** `Rookie / Normal / Hard / Expert` を単に「CPUが速く動く」のではなく、予測誤差、投球コースの分布、状況判断の賢さ、タイミングの許容幅、選手能力の適用強度で変更する。[D]

- `aimAssist` (0–3段階)、`batTimingAssist`、`fieldingAssist`、`runnerAssist`を独立。
- CPUの強さを変えても、同一能力の野手の物理トップスピードは難易度で極端に変えない。
- 乱数シードを固定したAI対戦のリプレイ検証を可能にする。

## 21. 決定事項・結論

1. 最新版の参照元は**2026–2027**。2024–2025、パワプロアプリ、WBSC eBASEBALLは同一仕様とみなさない。

6. 各実装をQA・リプレイ・出典・CIPI記録に結び付け、人間が実機で確認してから完了扱いにする。
